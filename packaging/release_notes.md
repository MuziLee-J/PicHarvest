## 本次更新（v1.1.0）

### 🛑 强制停止

识别过程中随时可以点「强制停止」，**0.3 秒内生效**。

之前"停不下来"的原因：OCR 推理是阻塞的 C++ 调用，线程层面无法中断。
现在把 OCR 放进独立子进程，点停止就是直接 `kill` 进程。

- 已完成的文件结果保留
- 正在处理的那一张会丢弃
- 单张识别超时（默认 60 秒）也会自动终止
- 可以在设置里关掉子进程隔离，退回原来的进程内模式

### 🧠 纠正记忆（用你的修改当训练数据）

你每次手工改的名字都会被记住。当**完全相同的 OCR 文本**再次出现时
（重跑同一批文件、同一份文档再次识别），直接沿用你的修正。

- 菜单「工具 → 纠正记忆」查看学到的内容，可导出 CSV
- 只存在本机，不上传
- **刻意不做模糊匹配**：同一套表单换个姓名时两段文本相似度 99%+，
  模糊匹配会把上一个人的名字安到这个人头上

### 📊 OCR 效果诊断

```bat
PicHarvest.exe --selftest        :: 自带自检，含强制停止验证
python tools/diagnose_ocr.py --root "D:\数据" --limit 5
```

诊断工具会对同一张图跑四种预处理强度，打印每行文字的置信度，
告诉你问题出在图像质量、命名字段还是模型能力。

### 📤 训练数据导出

菜单「工具 → 导出 OCR 训练数据」，会把**姓名所在的那一行**裁出来，
生成 PaddleOCR 可直接使用的 `train.txt`：

```
crops/00001.jpg	姓名：张三
crops/00002.jpg	姓名：王五
```

同时附 `review.csv` 供你核对标签。详见
[`docs/OCR_训练指南.md`](https://github.com/MuziLee-J/PicHarvest/blob/main/docs/OCR_训练指南.md)。

> 关于"能不能训练"：能，但识别模型吃的是**单行截图**，不是整张照片；
> 且建议 ≥500 条标注。先用「换 server 模型 + 调预处理 + 纠正记忆」，
> 最后才考虑微调。

### 其他改进

- 支持自定义识别/检测模型路径（换更强的预训练模型，不用训练）
- 报告与训练导出都能取到文本框坐标（用于精确定位命名行）

## 这个工具做什么

从一个大目录里**按路径层级**批量挑出指定图片，本地 OCR 识别文字后
以「来源文件夹_识别名称」命名，复制到新目录。

```
20250101/                              D:\整理结果\
├── CASE001/1440/SAMPLE_NA.jpg    →    ├── CASE001_张三.jpg
├── CASE002/1440/SAMPLE_NA.jpg    →    ├── CASE002_张三.jpg
├── CASE003/1440/SAMPLE_NA.jpg    →    └── CASE003_李四.jpg
└── CASE003/2880/SAMPLE_NA.jpg    ✗  规则是 1440，不会命中
```

**路径规则可自由配置**：

| 写法 | 含义 |
|---|---|
| `*` | 匹配恰好一层目录名 |
| `**` | 匹配任意层级目录 |
| `*/1440/SAMPLE_NA.jpg` | 所有一级目录下 `1440` 里的这张图 |
| `*/2880/*.jpg` | 所有一级目录下 `2880` 里的全部图片 |

## 三条安全承诺

| 承诺 | 实现方式 |
|---|---|
| **原始文件永不改动** | 扫描与 OCR 全为只读，唯一写盘动作是"复制"。测试用 SHA256 目录指纹逐条证明源目录零变化 |
| **目标文件永不覆盖** | 用 `O_CREAT\|O_EXCL` 独占创建，文件已存在时由**操作系统内核**报错，再自动改名 `-1`/`-2`/`-3` |
| **执行前必须确认** | 扫描与执行是两个独立阶段，看到完整来源路径与最终文件名之前，不写入任何文件 |

**完全离线**：图片与识别结果只在本机流转，程序不含任何上传逻辑。

## 主要功能

- **向导式四步**：设置 → 扫描（只读，列出来源路径供确认）→ OCR 与命名 → 执行
- **命名优先级**：① 历史修正 → ② 指定字段 → ③ 本地 AI 判断 → ④ 人工确认
- **重名处理**：自动追加 `-1`/`-2`/`-3`，并保留来源文件夹信息便于区分
- **批量可控**：表格支持筛选、排序、缩略图、勾选/取消、逐条改名
- **执行可控**：实时进度、暂停/继续/取消/**强制停止**
- **错误隔离**：单个文件损坏/失败不影响整个任务
- **可追溯**：全程日志 + CSV/JSON/Excel 报告 + SQLite 任务历史
- **可撤销**：只删除本任务生成的文件，且经四重校验后才删

## 系统要求

- Windows 10 / 11（64 位）
- 内存 4 GB 以上（OCR 时占用约 300–500 MB）

## 出问题怎么办

```bat
PicHarvest.exe --selftest
```

自检结果会写到 `%LOCALAPPDATA%\PicHarvest\selftest_report.txt`，里面包含
OCR 引擎、**子进程强制停止**、防覆盖机制的真实检测结果。
运行日志在 `%LOCALAPPDATA%\PicHarvest\logs\`。

杀毒软件若报警请选择"允许"——PyInstaller 打包的程序常被误报。
