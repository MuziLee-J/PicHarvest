# OCR 识别效果提升指南

> 结论先行：**先用"换模型 + 调预处理 + 纠正记忆"这三招，最后才考虑训练。**
> 训练能解决问题，但它对数据量的要求远高于直觉，用几十张图去微调
> 大概率会让效果变差。

---

## 一、先诊断：弱在哪一环？

```bat
python tools/diagnose_ocr.py --root "D:\示例数据\20250101" --template "*/1440/SAMPLE_NA.jpg" --limit 5
```

它会对同一张图用 4 种预处理强度各识别一次，并打印每一行的置信度。
看输出就能定位问题：

| 现象 | 说明 | 该做什么 |
|---|---|---|
| 文字读出来了，但只有某个字段没选中 | **不是 OCR 问题**，是命名字段没对上 | 改"命名字段"，或手工改一次（会记进纠正记忆） |
| 某些强度明显更准 | 图像质量问题 | 把"图像预处理"设成效果最好的那档 |
| 四种强度都读不出字 | 分辨率太低 / 失焦 / 光照太差 | 只能重拍，训练救不了 |
| 字读出来了但错字多（形近字） | 模型能力不足 | 换更强的预训练模型（见第二节） |
| 手写体识别差 | 通用模型对手写本来就弱 | 换专供手写的模型；训练需要大量手写标注 |

---

## 二、三条性价比最高的路（都不需要训练）

### 1. 换更强的预训练模型

内置的 RapidOCR 用的是**移动端模型**（体积小、速度快）。换成
PP-OCRv4 / PP-OCRv5 的 **server 模型**，精度通常有明显提升。

1. 从 PaddleOCR 官方模型库下载推理模型（`*_infer` 目录或 `.onnx` 文件）
2. 程序里：**OCR 设置 → 识别模型 → 浏览**，填入模型路径
3. 重新扫描并识别

> 这一步不需要标注、不需要 GPU，通常几分钟就能完成，
> 是"识别弱"最先该试的。

### 2. 调预处理

- **手机拍摄、光照不均** → 用「强力」（纠偏 + 锐化 + 二值化）
- **扫描件、清晰打印** → 用「标准」甚至「不处理」（过度处理反而降点）
- **小字** → 预处理会自动放大短边小于 720px 的图片

用 `diagnose_ocr.py` 对比四种强度的置信度，选最高的那档。

### 3. 纠正记忆（用你的修正当训练数据）

程序会记录你每一次手工改名的结果。当**完全相同的 OCR 文本**再次出现时
（重跑同一批文件、同一份文档再次识别），直接沿用你的修正，置信度 1.0。

- 打开：**工具 → 纠正记忆**
- 可导出 CSV 查看
- 只存在本机 SQLite，不上传

> 注意：程序**刻意不做模糊匹配**。同一套表单换个姓名时，两段 OCR 文本
> 相似度往往超过 99%，模糊匹配会把上一个人的名字安到这个人头上。

## 三、真的要做微调时

### 3.1 先看清代价

| 项目 | 要求 |
|---|---|
| 数据形态 | **单行文字截图**（不是整张照片）+ 对应文字 |
| 数据量 | 建议 ≥ 500 条，覆盖真实字体/拍摄条件；低于 100 条基本无意义 |
| 硬件 | GPU（CPU 训练慢到不实用） |
| 时间 | 从准备数据到验证效果，通常 1~2 天 |
| 风险 | 数据不干净 → 过拟合 → 通用能力退化 |

**微调适合的场景**：字体固定、版式固定、通用模型在特定字符上稳定出错。
**不适合**：样本杂乱、每张版式都不同、或者问题根本出在图像质量上。

### 3.2 用本程序导出数据

1. 先跑完一次完整任务，把不确定的名字**手工修正**（这一步决定了数据质量）
2. 菜单：**工具 → 导出 OCR 训练数据…**
3. 选择保存位置，得到：

```
训练数据_20261021_120000/
├── crops/
│   ├── 00001.jpg       ← 姓名所在行的截图
│   └── ...
├── train.txt           ← "crops/00001.jpg<TAB>姓名：张三"
├── manifest.csv        ← 来源路径、OCR 原文、裁剪坐标
├── review.csv          ← 待复核清单
└── 说明.txt
```

**为什么只导出姓名那一行**：整页里只有这一行经过人工校验。其余行的
文字是 OCR 自己的输出，拿来当标签等于教模型重复自己的错误。

**训练标签忠实于原图**：全角冒号就是全角冒号，不做归一化。

### 3.3 训练前必须做的复核

打开 `review.csv`，逐条核对"训练标签"一列。错一条就污染一条。
改完记得同步删除 `crops/` 里对应的图片和 `train.txt` 里的对应行。

### 3.4 PaddleOCR 微调

```bash
pip install paddlepaddle-gpu paddleocr

# 1. 准备字符字典（必须包含标签里出现的所有字符）
cp <paddleocr>/ppocr/utils/ppocr_keys_v1.txt ./

# 2. 修改 configs/rec/PP-OCRv4/ch_PP-OCRv4_rec.yml：
#    character_dict_path: ./ppocr_keys_v1.txt
#    Train.dataset.data_dir: <训练数据目录>
#    Train.dataset.label_file_list: [./train.txt]
#    Eval 同理，建议从训练集切 10% 做验证

# 3. 开始训练
python tools/train.py -c configs/rec/PP-OCRv4/ch_PP-OCRv4_rec.yml

# 4. 导出推理模型
python tools/export_model.py -c ... -o Global.pretrained_model=...
```

> 具体参数以你安装的 PaddleOCR 版本文档为准。本程序不负责训练，
> 只负责产出一份格式正确的数据集。

### 3.5 把新模型装回程序

1. 训练并导出推理模型（`*_infer` 目录或 `.onnx`）
2. 程序：**OCR 设置 → 识别模型 → 浏览**
3. 重新识别验证；效果不好就回退（清空该输入框即可）

## 四、常见误区

**"数据越多越好，先把几千张都导出来"**
导出的只有姓名行；如果这些行的名字你根本没核对过，那导出的是
模型的错误，不是标注。

**"用整张图训练"**
识别模型吃的是单行文字图。整页图是给**检测模型**用的，训练方式完全不同。

**"微调一下就应该全面变好"**
微调只在你提供的数据分布内提升。换一种表单、换一种字体，可能反而变差。
建议保留旧模型，按项目切换。

**"OCR 不准就是模型不行"**
先跑 `diagnose_ocr.py`。相当一部分"识别弱"其实是：
图片太小/太糊、名字字段配错了、或者名字在手写区域。
这些情况下换模型和训练都救不了。

## 五、本程序的边界

- **不做模型训练**：训练需要 GPU 与数百条标注，属于离线的一次性工作，
  不该塞进日常使用的工具里。
- **全部本地**：导出、纠正记忆、诊断都只读写本机文件。
- **可回退**：模型路径留空即回到内置模型，不会破坏原有可用性。
